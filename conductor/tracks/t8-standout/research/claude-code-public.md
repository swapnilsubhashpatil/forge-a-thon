# Claude Code agent-mode behaviour (public sources only)

Researched 18 Nov 2026. Sources: code.claude.com/docs (scraped via Firecrawl) and `CHANGELOG.md` in github.com/anthropics/claude-code (shallow clone, latest entry 2.1.327). No bundle, source or system-prompt material was used. Changelog references are `CHANGELOG.md:<line>` with the version heading that line falls under. Anything marked [unverified] is my inference.

The hooks reference page (code.claude.com/docs/en/hooks) timed out twice, so the Stop-hook rows below rely on the changelog only.

## M11: messages sent while the agent works (most important)

| Behaviour | Source (quoted) | Applies to Anvil how |
|---|---|---|
| Messages typed mid-turn are queued and do not interrupt | interactive-mode#queue-messages-while-claude-works: "Type a message and press `Enter` while Claude is working. Claude Code queues the message instead of interrupting the turn, and lists the queued entries in the conversation until it sends them." | The webview input stays enabled during a turn. Pressing Enter adds the message to a visible queue and leaves the turn running. |
| **Delivery point is the end of the current tool-call batch, inside the same turn** | interactive-mode#when-claude-code-sends-what-you-queued: "Messages: if you queue a message while Claude is running tool calls, Claude Code passes it to Claude as soon as those tool calls finish, within the same turn. When the turn ends with messages still queued, they go out without another key press, in the order you typed them" | This is the core M11 design. In `turnRunner`, after the tool results of a step are appended, drain the queue and append it as a user message before the next model request. If the turn ends with messages still queued, start a new turn with them automatically. |
| Commands are held until the turn ends | same section: "Commands and shell commands: Claude Code holds them until the turn ends, then runs them one at a time, keeping the order you queued them in" | Slash-style actions should run between turns, never inside one. |
| Queued messages are visibly pending | "Sent and queued messages show in gray until Claude starts responding to them"; CHANGELOG.md:467 (2.1.327 block): "the send-now hint under queued messages: it now says \"Queued\"" | Show queued messages greyed out with a "Queued" label, and switch them to normal style once delivered. |
| Queued messages can be taken back | "Press `Up` from the first line of the input box to take back the queued messages and commands ... puts them in the input box, one per line" | Each queued item gets an edit/remove control. This is cheap to build and avoids messages the user regrets sending. |
| "Send now" option | "To send what you queued without waiting, press `Ctrl+Enter` ... Running shell commands, subagents ... that work moves to the background and keeps running, and Claude reads your messages in the same turn. Only writing a response ...: Claude Code interrupts the turn and sends your messages next" | Optional for Anvil. A simpler version is to abort the stream and send the queue next. |
| Esc interrupts the turn, keeps completed work, then sends the queue | Esc row: "Stop the current response or tool call mid-turn so you can redirect. Claude keeps the work done so far. If you have messages queued, Claude Code sends them next." | Stop keeps the transcript and applied edits and then delivers the queue. It does not discard anything. |
| Feature history | CHANGELOG.md:11059 (0.2.108): "You can now send messages to Claude while it works to steer Claude in real-time"; :10662 (1.0.84): "Fix Claude sometimes ignoring real-time steering when wrapping up a task"; :10135 (2.0.68): "steering messages could be lost while a subagent is working" | Known failure modes to test: a message arriving during the final answer step must not be dropped, and the same applies while a subagent is running. |
| Remote "queue for later" must not land mid-turn | CHANGELOG.md:1034 (2.1.321): "Fixed a Remote Control message sent with \"Queue for later\" reaching Claude in the middle of the running turn" | Supports two delivery modes, steer (next step) and later (after the turn). [unverified that a later-mode exists outside Remote Control] |
| Mid-turn messages get no checkpoint | checkpointing#messages-sent-mid-turn-not-checkpointed: "a message you typed while Claude was still working can be marked No code restore. The marked message has no checkpoint of its own." | Only turn-starting prompts create restore points. |
| PostToolUse still runs when interrupted | CHANGELOG.md:1230 (2.1.319): "Changed PostToolUse hooks to run, with up to 10 seconds to finish, on tool calls that finish after a new message interrupts the turn" | Let in-flight tool calls finish and record their results. Do not orphan a `tool_use` that has no `tool_result`. |

## Other behaviours

| Behaviour | Source (quoted) | Applies to Anvil how |
|---|---|---|
| **M6** Todo list introduced | CHANGELOG.md:11104 (0.2.93): "Claude now has access to a Todo list that helps it stay on track and be more organized"; :10629 "Added /todos command"; :10997 "Improved todo list handling during compaction" | `update_plan` plus a live checklist matches this. Keep the plan through context trimming by re-injecting it. |
| **M6** Todo tools now gated per model | CHANGELOG.md:5724 (2.1.233): "Todo/task-tracking tools ... are no longer available on Opus 4.8, Sonnet 5, Fable 5, Mythos 5, and newer models"; :4725 (2.1.268): offered "only on Claude 3.x, Opus 4.0–4.7, Sonnet 4.0–4.6, Haiku 4.5" | Anthropic removed the tool for its strongest models. This supports offering `update_plan` mainly for weaker or local models (B3), and making it optional for strong ones. [unverified rationale] |
| **M2** Explore subagent | docs/en/sub-agents: "A fast, read-only agent optimized for searching and analyzing codebases ... Tools: read-only tools; Write and Edit are denied ... Claude specifies a thoroughness level: quick ..., medium ..., or very thorough"; model inherits parent (CHANGELOG.md:6568, 2.1.198: "now inherits the main session's model (capped at opus) instead of running on haiku") | A read-only subagent that denies `propose_edit` and `run_command` writes. Add a `thoroughness` parameter and use the same model by default. |
| **M2** Plan subagent | "Tools: read-only tools; Write and Edit are denied. Purpose: codebase research for planning ... exploration output stays in a separate context window while the main conversation remains read-only." (added CHANGELOG.md:10385, 2.0.28) | This is the same as Explore but used in plan mode. Anvil does not need it separately. |
| **M2** General-purpose subagent | "Tools: every tool available to subagents ... complex research, multi-step operations, code modifications" | Skip this one for Anvil, because a read-only subagent is the safer demo. |
| **M2** Result format and nesting | "The work is self-contained and can return a summary"; "a subagent at the limit does its delegated work itself and returns one summary"; default depth "up to three layers" (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`) | Only the final summary text goes back as the tool result. Anvil should use a nesting depth of 1. |
| **M4** Bash timeouts | CHANGELOG.md:11060 (0.2.108): "Introduced BASH_DEFAULT_TIMEOUT_MS and BASH_MAX_TIMEOUT_MS"; :10435 (2.0.19): "Auto-background long-running bash commands instead of killing them" | Use a default timeout with a per-call override capped at a maximum. When a command times out, background it and report that, rather than killing it silently. |
| **M4** Background commands | CHANGELOG.md:10709: "(Ctrl-b) to run any Bash command in the background so Claude can keep working (great for dev servers, tailing logs, etc.)" | Add a `background: true` flag on `run_command` with an output-file handle. |
| **M4** Large output | CHANGELOG.md:9934 (2.1.2): "large bash command outputs to be saved to disk instead of truncated, allowing Claude to read the full content"; :9988 (2.1.0): "truncating to 30K chars with file path reference" | Cap inline output at about 30K characters, keep the tail (where failures usually appear), and write the full output to a temp file the model can `read_file`. This matches the M4 "huge-output" test. |
| Checkpoints / rewind | checkpointing: "Every prompt you send that starts a turn creates a new checkpoint"; options "Restore code and conversation / Restore conversation / Restore code / Summarize from here"; "A file that only Bash commands changed isn't tracked" | Snapshot files before each turn's first edit. Offer restore for code, conversation, or both. Document that `run_command` changes are not covered. |
| **M8** Stop hooks as a done-gate | CHANGELOG.md:7017 (2.1.163): "Stop and SubagentStop hooks can now return `hookSpecificOutput.additionalContext` to give Claude feedback and keep the turn going"; :7452 (2.1.143): "stop hooks that block repeatedly looping forever — the turn now ends with a warning after 8 consecutive blocks (`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`)"; :8877 "infinite loop when API errors triggered stop hooks" | When the model tries to finish, run checks such as diagnostics or tests. On failure, inject feedback and continue, but cap consecutive blocks (Claude Code uses 8; Anvil's plan of one follow-up is stricter). Never block on API-error stops. |
| **M9/G1** Context gauge | CHANGELOG.md:9869: "`context_window.used_percentage` and `context_window.remaining_percentage` fields to status line"; :10827 (1.0.51): "Increased auto-compact warning threshold from 60% to 80%"; :9801: blocking limit "intended ~98%" of the effective window, which "reserves space for max output tokens" (:9853) | The gauge should show used % against the effective window (context minus max output). Warn at about 80%, and compact or trim before about 95–98%. [exact auto-compact trigger not documented] |
| /context breakdown | CHANGELOG.md:1218: "each list keeps its 10 largest rows"; :3630 "MCP server instructions ... appear as their own row" | A per-category token breakdown (system, tools, files, history) is a strong demo feature. |
| Plan mode | sub-agents doc: main conversation "remains read-only" in plan mode; CHANGELOG.md:10217: "Added feedback input when rejecting plans, allowing users to tell Claude what to change"; :1247: "Fixed Claude carrying out an unapproved plan after a window reload" | A read-only mode in which a rejected plan carries a reason back to the model. Plan approval has to be persisted. |
| Rejected edits / permission denials | CHANGELOG.md:792: "a collapsed tool call looking as if it ran after you rejected it with a reason: it now shows \"Not run · rejected\""; :9848 "provide feedback when accepting permission prompts"; interactive-mode: Esc on a permission prompt "declines the action, the same as No without a comment" | Return a tool_result such as "User rejected this edit" plus an optional comment. In the UI, label the call "Not run · rejected". |
| **M7** Loop/stuck handling | No documented guard against repeated identical tool calls. The only loop caps found are for Stop hooks (8 blocks) and `/loop` keepalive. [unverified: none exists publicly] | Anvil's M7 (nudge on the 3rd repeat, cancel on the 5th) would be a differentiator rather than a copy. |
| Edits trigger diagnostics | CHANGELOG.md:173 (2.1.327): "[VSCode] ... queued edits share one wait for new problems; a problem may be reported with a later edit" | After `propose_edit`, attach new VS Code diagnostics to the result. This supports M8. |
